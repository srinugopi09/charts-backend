These are the questions that I got from front end team,  Frontend Integration — Questions for Backend

1. A2UI event_data.messages format (blocks frontend work)

When GET /api/threads/{thread_id}/messages returns a tool result with event_data.a2ui === true, what format are event_data.messages stored in?

Option A — Backend wire format (what the agent originally produced):


{
  "component": "Graph",
  "id": "chart-1",
  "graphType": "bar",
  "title": "Revenue",
  "data": { "labels": [...], "datasets": [...] }
}
Option B — A2UI spec format (post-transformation):


{
  "component": { "Graph": { "graphType": "bar", "title": "Revenue", "data": {...} } },
  "id": "chart-1"
}
This matters because the frontend has a transformation layer (flattenBackendComponent) that converts A → B. If you store format B, replaying through that layer would double-transform and break rendering.

2. Does the agent use initialMessages from the request or its own persisted history?

Currently the frontend sends the last 50 user messages in initialMessages on every POST /api/agent/run. Now that the backend persists all conversation events:

Does the agent read conversation context from its persisted state (ignoring initialMessages)?
Or does it still rely on initialMessages from the request?
If persisted, the frontend can stop sending history and just send the new message — simpler and avoids duplication.

3. Message pagination

GET /api/threads/{id}/messages has no limit/offset. Is this intentional? For long conversations with many tool calls, the response could get large. Any plan to add pagination, or should the frontend assume the full list is always returned?

4. Auto-title

Thread titles default to null. Who is responsible for generating them?

Option A: Frontend truncates the first user message and PATCHes it
Option B: Backend auto-generates a title after the first run completes
Option C: Frontend responsibility, but deferred (implement later)
5. Chart JSON in SSE stream

The backend currently sends chart config as a TEXT_MESSAGE in the SSE stream (which the frontend detects and filters out). Does this behavior continue unchanged with persistence, or will chart data only come through TOOL_CALL_RESULT events going forward?
